# 县域食品安全风险处置台

本地运行的食品安全监管流程演示。使用脱敏模拟数据，把风险线索、专项整治、县级分派、乡镇派发、网格核查、复核销号和操作记录串成一条可点击的流程。

## 范围

- 县级监管员：查看风险清单，发起专项整治，分派、退回或销号任务。
- 乡镇负责人：接收属地任务，派发给本乡镇网格员，并完成乡镇复核。
- 网格员：只可提交分派给自己的现场核查结果，必须填写发现项和整改结果。
- 风险分级：红、橙、黄、评分和来源均为演示数据；不使用真实监管数据，也不输出执法结论。

任务状态固定为：`待分派 → 待乡镇派发 → 待网格核查 → 待乡镇复核 → 待县级复核 → 已销号`。县级销号后，对应风险状态会同步变为“已处置”。

法规依据查询与处置流程分开：如需演示食品法规 RAG，可作为独立的依据查询工具；本项目不内置法规库，也不会把生成内容当作执法依据。

这不是生产系统。没有外部接口、真实地图、移动端离线、附件取证或真实预测模型；登录会话仅保存在内存中，服务重启后需要重新登录。所有最终处置仍需监管人员判断。

## 运行

```powershell
python app.py
```

打开 `http://127.0.0.1:8092`。也可以双击 `启动项目.bat`。

账号：`county`、`town_a`、`town_b`、`town_c`、`grid_a`、`grid_b`、`grid_c`；统一密码：`DemoFood!2026`。

本地数据保存在 `data/food_safety.db`，已忽略，不会提交到 GitHub。

## 自检

```powershell
python -m unittest -v test_app
```

测试会使用独立的临时数据库，覆盖伪造 Cookie、无效任务与风险编号、跨乡镇错误分派，以及“县级—乡镇—网格—乡镇—县级”的销号闭环。
